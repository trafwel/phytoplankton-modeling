# Walkthrough — Phase 3.3: Temporal Alignment

Goal: get OFES temperature (3-day) and PFT chlorophyll (monthly) onto **one common
monthly time axis**, so each row of the eventual model table is a single
(month, grid-cell) with both temperature and chlorophyll information. Written for
someone newer to pandas/xarray time handling.

---

## The core situation

- **PFT is monthly.** That's the binding constraint — the diatom/nano split isn't
  offered finer. So the joint analysis is **monthly**.
- **OFES is 3-day.** ~10 snapshots per month.
- **Overlap window:** 1998-01 … 2014-12 = **204 months**.

So OFES needs to be brought to monthly. But — and this is the important part —
**how** you bring it to monthly depends on what the OFES data is being used for.

## The branch you must not miss

OFES temperature feeds the pipeline in **two different ways**, and they need
different temporal handling:

1. **As a monthly-mean field** (a model *feature*: "how warm was this cell this
   month, and how anomalous"). → simple monthly average of the 3-day snapshots.

2. **As the input to marine-heatwave detection** (Phase 4). Hobday MHWs are defined
   on the *sub-monthly* time series — you need the 3-day resolution to detect
   "temperature above the 90th-percentile threshold for a sustained spell." If you
   average to monthly *first*, you destroy exactly the structure the MHW algorithm
   reads. → **keep the 3-day series intact for Phase 4**, run detection there, and
   only *then* aggregate the resulting MHW metrics (days-in-MHW, max intensity,
   cumulative intensity) to monthly.

Practical consequence: **don't throw away the 3-day OFES file.** 3.3 produces a
monthly-mean SST for pairing, but Phase 4 still consumes the original 3-day data.
The MHW-metrics-to-monthly step happens after Phase 4 and rejoins here.

## Step 1 — monthly-mean OFES SST

Average each month's 3-day snapshots into one value per cell per month
(NaN-aware, so land stays land). In xarray this is a `resample` on the time axis
followed by a mean. Each month has ~10–11 snapshots; a plain mean handles the
uneven counts fine.

## Step 2 — the month-anchor gotcha (the classic silent bug)

When you turn dates into "months," different tools label the month differently:
- pandas `resample("1M")` labels each month at its **end** (e.g. 2004-01-31).
- `resample("MS")` labels at the **start** (2004-01-01).
- The PFT file has its own monthly stamps (roughly mid/first of month).

If OFES months are labeled 2004-01-31 and PFT months are 2004-01-01, a naive join
**silently produces all-NaN** because the timestamps don't match exactly. The fix:
collapse both to a **year-month key** (a pandas `PeriodIndex` of `freq="M"`, or just
normalize both to the first of the month) before joining. Then Jan-2004 matches
Jan-2004 regardless of day. Do this deliberately; it's the single most common way
these merges go wrong.

## Step 3 — trim both to the overlap and align

Restrict both to 1998-01 … 2014-12 (204 months) and align on the common monthly
index. After alignment both should report exactly 204 time steps. PFT L4 is
gap-filled and OFES 3-day is continuous, so you expect no missing months — but
verify the count, don't assume it.

## Step 4 — (later, after Phase 4) aggregate MHW metrics to monthly

Once Phase 4 has produced per-3-day MHW outputs, summarize each month into
features: number of MHW days/steps that month, monthly max intensity, monthly mean
SST anomaly, cumulative intensity. These monthly features then join the same
204-month index as the PFT target. (Placeholder here; revisit after Phase 4.)
