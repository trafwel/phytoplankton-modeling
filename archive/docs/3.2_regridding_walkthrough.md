# Walkthrough — Phase 3.2: Regridding the two datasets onto one grid

This is where OFES temperature and the PFT chlorophyll finally live on the same
grid, so you can do math between them. Written for someone newer to xarray/xesmf.
No finished code — steps + a fill-in skeleton.

---

## Why this step exists

The two datasets cover the same Arabian Sea but on incompatible grids:

| | OFES temperature | PFT (DIATO/NANO) |
|---|---|---|
| resolution | 0.1° (~11 km) | ~0.042° (4 km) |
| longitude convention | 0–360 (values 50–75) | −180/180 (values 50–75) |
| latitude range | −74.95 … 74.95 @0.1° | −89.98 … 89.98 @0.042° |
| cadence | 3-day | monthly |

Cell (i, j) in one file is a *different patch of ocean* than cell (i, j) in the
other, so you can't correlate them directly. Regridding resamples one dataset onto
the other's grid so every cell refers to the same location. (Time is a separate
concern — handled in 3.3. Regridding is purely spatial.)

## Decision 1 — which grid is the target?

**Regrid the fine PFT (4 km) onto the coarse OFES (0.1°) grid.** Going fine → coarse
is the honest direction: you're averaging real 4 km detail into each bigger cell,
not inventing resolution. It also keeps files smaller. So the **OFES 0.1° Arabian
Sea grid is the common target**; the PFT gets resampled to it.

## Decision 2 — which regridding method?

Use **conservative** (area-weighted averaging). Reasons: (a) fine → coarse means
each OFES cell contains many PFT cells, and conservative correctly averages *all*
of them rather than sampling one point (bilinear); (b) it preserves the field's
overall mean/integral, which is the physically right behavior for a concentration
like chlorophyll. Bilinear would be the choice only if you were going coarse → fine
on a smooth field.

Conservative regridding needs **cell corner coordinates (bounds)**, not just
centers. For these regular lat/lon grids, xesmf can build the bounds automatically,
or you supply `lon_b`/`lat_b` arrays. Just be aware the error "conservative needs
bounds" means exactly this.

## Decision 3 — harmonize the longitude convention first

OFES is 0–360, PFT is −180/180. For the Arabian Sea (50–75°E) both conventions give
the same positive numbers, so there's **no wraparound problem here** — but xesmf
still wants the two grids described consistently. Before building the regridder,
put both longitude coordinates on the same convention (simplest: leave both as the
50–75 positive values you already have). Bake this into the code so it's explicit,
even though for this box it's a no-op.

## The mask / NaN gotcha

Both datasets have `NaN` over land (and PFT has cloud/quality gaps). Naive
conservative regridding can smear NaNs or treat them as zeros, corrupting coastal
cells — exactly the upwelling zone you care about. Handle it deliberately: regrid
with NaN-aware settings (xesmf's `skipna=True` and a sensible `na_thres`, which
controls how much missing data a target cell tolerates before it becomes NaN
itself). After regridding, re-confirm the land mask looks right.

---

## Step-by-step

1. **Load both** (lazily): OFES Arabian Sea surface temp (target grid), and the PFT
   `DIATO`/`NANO` (source to be moved).
2. **Harmonize longitude** convention on both (no-op values here, but make it explicit).
3. **Define the target grid** — an xarray object holding just the OFES lat/lon (and
   their bounds). This is the grid everything will be resampled to.
4. **Build the regridder** once: `xesmf.Regridder(source, target, "conservative")`.
   This computes the weights (the slow step). **Save the weights to a file** so you
   never recompute them.
5. **Apply** the regridder to `DIATO` and `NANO` → they now sit on the OFES 0.1°
   grid, still with their full monthly time axis.
6. **Handle NaN/mask** (skipna/na_thres), then re-apply/verify the land mask.
7. **Save** the regridded PFT to `data/interim/` (e.g. `pft_on_ofes_grid.nc`).
