# Walkthrough — 1.2 Satellite PFT (Diatom/Nano Chlorophyll) Acquisition

Guide for *you* to download the diatom and nanophytoplankton chlorophyll fields
that are the model **target** (and, per your spec, double as validation).
Everything here is grounded in the official Copernicus Marine Toolbox
documentation and the product page. Written assuming little pandas/numpy
experience, so the inspection steps explain each idea.

---

## What you're getting and why it's the right product

`DIATO` and `NANO` are provided as **separate chlorophyll variables** in this
product, so you recover your spec's DCHL and NCHL directly — no haptophyte
proxy. `DIATO` = DCHL, `NANO` = NCHL.

| Thing | Value |
|---|---|
| Product ID | `OCEANCOLOUR_GLO_BGC_L4_MY_009_104` |
| DOI | 10.48670/moi-00281 |
| Producer | ACRI-ST (Copernicus-GlobColour) |
| Coverage | Global, **1 Sep 1997 – present**, 4 km |
| Lon/lat convention | −180…180 (toolbox transposes automatically; see below) |
| Format | NetCDF-4 |
| Access | `copernicusmarine` Python toolbox / CLI (free CMEMS account) |
| PFT variables (chlorophyll) | `DIATO`, `NANO`, `PICO`, `MICRO`, `HAPTO`, `DINO`, `GREEN`, `PROKAR`, `PROCHLO`, + total `CHL` |
| Cadence you'll use | **Monthly (P1M)** — the PFT split is monthly only |
| dataset_id | **`cmems_obs-oc_glo_bgc-plankton_my_l4-multi-4km_P1M`** ✅ confirmed against the catalog's dataset list |

**The cadence decision (read before downloading).** The diatom/nano split
exists **only at monthly resolution**. Your OFES SST is 3-day. So the whole
joint model runs **monthly**: monthly `DIATO`/`NANO` as the target, MHW metrics
computed on the 3-day SST then aggregated to monthly features. Joint window
1998–2014 → ~204 monthly steps per grid cell. (This is why checklist Phase 3.3
was switched to a monthly common grid.)

## The three toolbox commands you use

The toolbox exposes each capability as both a **CLI command** and a **Python
function**; they take the same parameters. The documented workflow is:

1. **`login`** — authenticate once; credentials are cached to
   `$HOME/.copernicusmarine` so `subset` never has to prompt again.
2. **`describe`** — "explore product metadata"; use it to read off the exact
   `dataset_id` and variable short-names before downloading. The docs state the
   datasetID "can be found via the `describe` command."
3. **`subset`** — "retrieve an extract of the dataset... selecting specific
   variables, geographical areas, time ranges and depth ranges." The download.

## Step-by-step

**Step 1 — Account + install.** Register at `data.marine.copernicus.eu/register`.
Install with `pip install copernicusmarine`. Run `copernicusmarine login` once
and enter your credentials; they're cached from then on.

**Step 2 — Confirm the dataset_id and variable names.** A product holds several
datasets; you want the monthly plankton one. List them and read off the exact
strings before committing:
`copernicusmarine describe --contains OCEANCOLOUR_GLO_BGC_L4_MY_009_104`
Look for the `dataset_id` whose name contains `plankton` and `P1M`, and confirm
the variables are named `DIATO`, `NANO`, `CHL`.

**Step 3 — Dry run first.** The docs provide `--dry-run` ("runs query without
downloading data"). Run your full command with `--dry-run` appended to confirm
it resolves and to see the reported size before committing.

**Step 4 — Download the subset.** Run the `subset` command (assembled at the
bottom). It writes one NetCDF to `data/raw/pft/`. Because L4 is 2-D surface,
you give **no depth argument**.

**Step 5 — Inspect it (pandas/numpy-friendly).** Open the file and look:
  - `xarray.open_dataset("data/raw/pft/pft_arabiansea_1998_2014.nc")` returns a
    `Dataset` — think of it as a labeled container of grids. Printing it shows
    the **dimensions** (expect `time ≈ 204`, plus `latitude`, `longitude`),
    the **coordinates** (the actual lat/lon/time values), and the **variables**
    (`DIATO`, `NANO`, `CHL`).
  - Pick one variable with `ds["DIATO"]`. Selecting one month with
    `ds["DIATO"].isel(time=0)` gives a single 2-D map. `.isel` means "select by
    integer position" (0 = first month); `.sel` means "select by label" (e.g. a
    date). This is the one pandas/xarray idea you'll reuse everywhere.
  - `.plot()` on that 2-D slice draws a quick map. You should see the
    Oman/Somalia upwelling maximum — high `DIATO` along the coast in the
    summer-monsoon months.
  - Land and cloud gaps show up as `NaN` ("not a number", the standard
    missing-data marker). numpy has `np.nanmean`, `np.nanmax` etc. that ignore
    `NaN` — use those instead of plain `mean`/`max` so gaps don't poison the
    stats.

**Step 6 — Build the ratio (later, in preprocessing).** The DCHL/NCHL signal is
`DIATO / NANO`. You'll compute it during Phase 3, guarding against divide-by-zero
where `NANO` is ~0. Note it now; don't do it in the raw file.

**Step 7 — Keep the uncertainty/flag layer.** If the product ships a per-pixel
uncertainty variable, keep it — Phase 8 weights validation by it.

**Exit check.** Time span continuous and monthly; `DIATO`/`NANO` present and
physically plausible; grid ready to regrid onto the OFES 0.1° target (Phase 3.2).

## `subset` parameter reference (from the official signature)

Documented parameter → what the docs say → your value.

- **`dataset_id`** (required): "the datasetID... found via `describe`." →
  `cmems_obs-oc_glo_bgc-plankton_my_l4-multi-4km_P1M` (confirm Step 2).
- **`variables`** / `-v` (repeatable): "List of variable names to extract." →
  `DIATO NANO DINO CHL`. (`DINO` = dinoflagellates — the "winner" when diatoms
  collapse in the Arabian Sea; enables a diatom-dominance index `DIATO/(DIATO+DINO)`
  and validates the documented diatom→dinoflagellate regime shift. Optionally add
  `DIATO_uncertainty NANO_uncertainty` for Phase 8.)
- **`minimum_longitude` / `maximum_longitude`** / `-x -X`: "the value will be
  transposed to the interval [-180; 360[." → `50` / `75`. *This auto-transpose
  is why no 0–360 conversion is needed here* (unlike raw OFES).
- **`minimum_latitude` / `maximum_latitude`** / `-y -Y`: "float from -90 to +90."
  → `5` / `25`.
- **`minimum_depth` / `maximum_depth`**: positive float or 0. → **omit** (L4 is
  2-D surface, no depth axis).
- **`start_datetime` / `end_datetime`** / `-t -T`: dateutil formats; wrap in
  quotes. → `"1998-01-01"` / `"2014-12-31"`.
- **`coordinates_selection_method`**: `inside|strict-inside|nearest|outside`,
  default `inside`. → default.
- **`service`** / `-s`: docs — "`timeseries`: long timeseries over a small area"
  (claims 5×–100× faster). Your case exactly. → `timeseries`.
- **`output_directory`** / `-o` → `data/raw/pft`.
- **`output_filename`** / `-f` → `pft_arabiansea_1998_2014.nc`.
- **`skip_existing`** vs **`overwrite`** (mutually exclusive): skip re-downloads
  on re-run, or overwrite in place. → `skip_existing` if you plan to re-run.
- **`file_format`**: defaults to NetCDF for gridded data. → omit.

## Assembled reference command (only after the above)

CLI form for your pull — run once with `--dry-run` appended, then for real:

```
copernicusmarine subset \
  -i cmems_obs-oc_glo_bgc-plankton_my_l4-multi-4km_P1M \
  -v DIATO -v NANO -v DINO -v CHL \
  -x 50 -X 75 -y 5 -Y 25 \
  -t "1998-01-01" -T "2014-12-31" \
  -s timeseries \
  -o data/raw/pft -f pft_arabiansea_1998_2014.nc
```

Short flags map to the parameters above: `-i` dataset-id, `-v` variable
(repeatable), `-x/-X/-y/-Y` bbox, `-t/-T` time range, `-s` service, `-o/-f`
output. There is a Python-API equivalent (`copernicusmarine.subset(...)`) with
the same argument names spelled out (`minimum_longitude=50`, etc.) if you prefer
scripting it.

## Notes carried into later phases
- **Monthly cadence is the binding constraint** → the joint pipeline is monthly;
  MHW metrics get aggregated to monthly features (Phase 3.3).
- **Spatial:** PFT is 4 km, OFES is 0.1° (~11 km). Regrid PFT → OFES grid
  (coarser target), area-weighted, in Phase 3.2.
- **Validation reuse:** total `CHL` here is your independent chlorophyll-a check
  (Phase 8); cross-check against ESA OC-CCI for a fully independent source.
- **Lon convention:** toolbox transposes to [-180;360[ for you; keep the OFES
  0–360 convention straight when the two grids meet in Phase 3.2.
